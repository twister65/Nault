# Nault 1.19.3 — twister65 fork

This release belongs to the independently maintained [twister65/Nault](https://github.com/twister65/Nault) fork and is not an official Nault/Nault release.

## Highlights since v1.19.2

- **Electron 45.3.1 ([#73](https://github.com/twister65/Nault/pull/73)).** Upgrade Electron Desktop from 44.11.2 to the tested **45.3.1** release, keeping Angular 22 and the existing Linux, Windows and macOS packaging workflows. Electron 45.3.2 is **not** part of this release; the maintainer elected to ship the version that completed real-device testing.
- **Ledger native HID confirmations without premature timeout ([#100](https://github.com/twister65/Nault/pull/100)).** Interactive device confirmation of sends and on-screen addresses on Electron Desktop USB is no longer terminated by the former fixed 30-second HID-read deadline or the former IPC signing deadline. Non-interactive operations retain bounded waits. The signing session holds native transport exclusivity to prevent health checks from interrupting it.
- **Respect explicitly rejected Ledger receives ([#73](https://github.com/twister65/Nault/pull/73)).** A receive rejected on the Ledger (0x6985), including with Nano app Auto Receive disabled, is not automatically re-presented for signing after balance refresh, WebSocket confirmation or reconnect during the current wallet session. Funds stay pending and can still be received manually; other pending sources remain eligible. New regression tests cover refusal handling.
- **PWA validation and testing-environment fix.** Shared receive-rejection handling was also validated on the ChromeOS PWA with Nano X Bluetooth. The test site's Angular service-worker hash mismatch was traced to Vercel Toolbar HTML injection and resolved by disabling Vercel preview/production feedback on the dedicated test project. This Vercel setting is not an application code change and is not needed for normal Apache-hosted PWA deployments.

## Downloads by platform (after tag-triggered publication)

- **Windows x64:** EXE installer.
- **macOS Intel x64:** DMG and technical update ZIP.
- **macOS Apple Silicon arm64:** DMG and technical update ZIP. **Required** before release publication; do not skip the macOS arm64 job.
- **Linux x64:** AppImage, DEB (Ubuntu/Debian/Mint), RPM (Fedora/openSUSE) and Pacman (Arch/Manjaro).
- Update metadata, blockmaps and SHA-256 checksums are produced and validated by the release workflow.

## Validation and limitations

The maintainer reported successful functional testing of the **pre-release PR #73 build** on:
- **Ubuntu:** a real Ledger Nano S; critical wallet flows tested on Electron 45.3.1.
- **Windows:** a real Ledger Nano X over Bluetooth and USB; pending receives, explicit rejects, further receives, send after USB reconnection, and Ledger operation recovery.
- **ChromeOS PWA:** a real Ledger Nano X over Bluetooth, intentional rejection handling, pending receives, successful sends, and app update after correcting the Vercel test deployment.

All 30 checks on the final #73 PR commit were successful or intentionally skipped before the merge, including Angular tests, dependency/security checks, desktop packaging and isolated Linux package installation/removal smoke checks. These results are not a claim that the *v1.19.3 release artifacts* have already been downloaded and installed.

**Not yet manually validated on v1.19.3 release artifacts:** macOS Intel/Apple Silicon installation and physical Ledger signing on macOS; Fedora/openSUSE and Arch/Manjaro native installation; every new Windows/Linux installer. Packaging success and smoke checks are distinct from physical-device validation. Unsigned macOS builds are not claimed to be signed or notarized.

## Release procedure

Preparing this branch does **not** create or publish a tag or release. After merging the release-preparation PR into `master` and checking its exact commit and CI, the maintainer should create and push the annotated tag **`v1.19.3`** pointing to that `master` commit.

Version consistency required by the tag workflow:
- `package.json.version`: `1.19.3`
- `package-lock.json.version`: `1.19.3`
- `package-lock.json.packages[""].version`: `1.19.3`

The tag triggers [Electron App Release](https://github.com/twister65/Nault/actions/workflows/electron_hash.yml). Publication occurs only after platform packages, including Apple Silicon, Linux install/removal checks, release assets and checksums pass. A failed or busy `macos-15` runner should be re-run rather than excluded from the release.

## Apache PWA deployment

Publishing the GitHub release does not update the separately hosted Apache PWA. After validating the published release, deploy the exact tag when desired:

```bash
~/bin/deploy-nault-master.sh --tag v1.19.3
```

Verify the version and embedded commit in the PWA/Desktop About pages, balances and representatives, Ledger USB/Bluetooth connection and refusal-safe receive. Keep the previous Apache release available for rollback.
