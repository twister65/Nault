# Nault 1.19.5 — twister65 fork

This is a release of the independently maintained [twister65/Nault](https://github.com/twister65/Nault) fork, **not** an official upstream Nault/Nault release.

## Highlights since v1.19.4

- **Electron 45.4.1 ([#113](https://github.com/twister65/Nault/pull/113)).** Updates Desktop from **45.3.2 to 45.4.1**, keeping the Electron 45 major line. The dependency version is pinned in the manifest, npm v2 lockfile, CI security assertion and regression test. The updated Electron dependency was reconciled against the already-merged Angular 22.3.0 lockfile rather than reverting framework changes. The Electron release embeds Chromium **156.0.8078.100** and Node.js **24.22.3**, according to the Electron maintenance PR. CI cannot replace physical Ledger validation.
- **Angular 22.3.0 ([#114](https://github.com/twister65/Nault/pull/114)).** Upgrades the Angular framework and CLI/Build tools from **22.2.x to 22.3.0** and regenerates the locked npm dependency graph. Retains the existing TypeScript 6.0.x / RxJS 7.x integration. The Web/PWA frontend and Electron renderer both use this framework.
- **Prevent duplicate manual/automatic receive after hot-wallet unlock ([#112](https://github.com/twister65/Nault/pull/112)).** Resolves a race where clicking **Receive** while a hot wallet was locked could overlap with automatic processing triggered by unlocking. The same Nano receive block could be submitted twice: the first succeeded, then the second reported `Old block` and displayed a misleading error. Account reservations and single-flight processing now prevent duplicate publication while preserving retries after genuine failures.
- **Localized Nano merchant mode and symbols ([#111](https://github.com/twister65/Nault/pull/111)).** Translates the Merchant Mode checkout, QR generation, partial-payment prompts, confirmation and copied payment information in English, French, German and Spanish. The interface uses the official Nano double-stroke graphic where appropriate, the single-stroke **Ӿ (U+04FE)** for text and amounts, and a localized Nano accepted-here badge. Payment calculation, signed blocks and the RPC protocol are not changed by the translation work.
- **Traditional Chinese (Hong Kong) ([#115](https://github.com/twister65/Nault/pull/115)).** Adds **繁體中文（香港） / zh-HK**, with **897 translated keys**, Electron native menu/updater/Bluetooth prompts and Hong Kong-specific Nano merchant badge (`blue-zh-hk-var1.svg`). Traditional Chinese language variants are mapped to the new locale; unsupported Simplified Chinese keeps the English fallback. Includes tests for dictionary parity, interpolation, language selection and badge routing.

## Downloads (after the release tag and all publication gates complete)

- **Windows x64:** NSIS EXE installer.
- **macOS Intel x64:** DMG and updater ZIP.
- **macOS Apple Silicon arm64:** DMG and updater ZIP. Keep the arm64 build enabled; do not silently omit it if the runner is busy.
- **Linux x64:** AppImage, DEB (Ubuntu/Debian), RPM (Fedora/openSUSE) and Pacman (Arch/Manjaro).
- The release workflow also assembles updater metadata, SHA-256 checksums, Linux install/remove smoke tests and verifiable provenance attestations for native artifacts.

## Validation and limitations

- **Before tagging:** Require the release preparation PR's Angular 22 validation, security audit, CodeQL, lint, wallet regression tests and Merge gate to pass against the combined dependency graph. Inspect the separate Windows, Linux, macOS x64 and arm64 packaging results, and rerun any failed packaging job.
- **Manual tests still required on the exact release candidate:** hot-wallet manual receive after the unlock prompt has disappeared, automatic receive, cancel/retry, standard send/receive, balance/representative refresh, PWA update/reconnection/offline behavior, merchant QR checkout and translations (including zh-HK), and physical Ledger Nano S Plus WebHID / Nano X Bluetooth & USB signing, reconnection and deliberate rejection (`0x6985`). Do not claim these as validated solely because CI passed.
- **Packaging versus hardware:** successful builds on Windows/Linux/macOS do not prove fresh installation or Ledger hardware operation on the final tagged binaries. macOS packages are not represented as notarized or signed unless that is independently verified.
- **Windows browser/PWA WebAuthn PRF:** the optional device-unlock control remains disabled on Windows pending a verified upstream fix; password unlock continues to work. This restriction is not removed by v1.19.5.
- No GitHub release assets or Apache-hosted PWA have been published as part of preparing these release notes.

## Release and publication procedure

Preparing the branch and notes **does not create or push a tag**, publish GitHub release assets, or deploy the production PWA.

1. Merge the release preparation PR into `master` only after CI and review; verify all three version sources match **1.19.5**: `package.json.version`, `package-lock.json.version`, `package-lock.json.packages[""].version`.
2. After explicit maintainer approval, create and push **annotated tag `v1.19.5`** pointing to the exact validated `master` commit. The tag triggers [Electron App Release](https://github.com/twister65/Nault/actions/workflows/electron_hash.yml).
3. That tag workflow **automatically publishes** the GitHub release after Windows, macOS Intel/Apple Silicon and Linux assets, verification of checksums, provenance, and installation smoke gates succeed. Pushing this tag is therefore a publication action, **not** merely a draft.
4. Review GitHub release artifacts, update feeds, signatures/provenance, the release version and source commit before any separate production PWA deployment.

### Apache-hosted PWA (separate, opt-in deployment)

When the production PWA is approved for deployment, use the existing host procedure:

```bash
~/bin/deploy-nault-master.sh --tag v1.19.5
```

Confirm **About Nault** shows the expected version/commit; retest Ledger USB/BLE, RPC/WebSocket, PoW failover, new Chinese translations, incoming receipts and the service-worker update. Retain v1.19.4 for rollback.
