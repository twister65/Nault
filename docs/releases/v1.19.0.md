# Nault 1.19.0 — twister65 fork

This is an independently maintained release of [twister65/Nault](https://github.com/twister65/Nault), not an official release from the upstream Nault/Nault project.

## Highlights since v1.18.8

- **More resilient Nano RPC and WebSocket selection.** Versioned node registry, background health and chain-consensus ranking, independently managed local nodes and improved automatic failover; keep explicit RPC choices stable across temporary network loss, stale responses and airplane-mode reconnection. Silent and cleaner first launch without a wallet.
- **Independent proof-of-work (PoW) selection.** The wallet RPC server and work source no longer depend on each other. Best-available PoW chooses an unlocked Nano.to API key only when available; otherwise use the supported Twister32 RsNano work endpoint, with a WebGL fallback on eligible desktop/ChromeOS environments. Android PWA uses external work. Retain the configured RPC when work fails.
- **Optional encrypted Nano.to PoW API keys.** Local AES-256-GCM vault with WebCrypto/PBKDF2, per-session unlock, multiple labeled keys, active-key selection and local-only encrypted storage. The provider is a third-party service with its own [privacy policy](https://rpc.nano.to/privacy) and [terms](https://rpc.nano.to/terms). Never place a key in an URL; a saved key can authorize only the dedicated Nano.to HTTPS PoW endpoint.
- **Vault safety and clearer UI (PR #88).** The *vault password* wording is translated in French, English, German and Spanish. The source-PoW and Nano.to legal disclosures are keyboard/touch-accessible. After three consecutive failed vault-password authentication attempts, Nault erases the **PoW API-key vault only**; the counter persists across reloads and successful unlock resets it. Wallets, seeds and Ledger data are unaffected. The encrypted vault and keys cannot be recovered after erasure.
- **Onboarding and language.** German translations, operating-system locale detection with English fallback, localized PWA update messages, and disabled Send/Receive navigation when no wallet is configured.
- **Expanded desktop packaging.** Linux x64 AppImage plus native DEB, RPM and Pacman packages (including application-menu integration), Windows installer and macOS Intel/Apple Silicon artifacts. Release downloads are grouped by platform and integrity metadata is checked.

## Security, compatibility and validation

- Maintains Angular 22, Electron desktop and PWA targets. Existing Ledger Nano S, Nano S Plus and Nano X compatibility and transport restrictions remain in scope.
- PR #88 validation: Angular tests, lint, CodeQL, dependency audit, RPC/PoW regression jobs and multiplatform packaging CI passed. The encrypted vault's three-failure deletion, counter persistence, UI warnings and basic no-key PoW selection were exercised on the protected Vercel staging deployment using dummy credentials.
- **Hardware and real-network acceptance is still recommended** after release: Android PWA, Chromebook, Linux/Windows Desktop and supported macOS with Ledger, real authorized Nano.to generation/CORS, Twister32/WebGL fallback, network recovery and PWA update. CI and fake-key tests cannot prove physical Ledger or third-party PoW success.
- The optional PoW credential store is independent of the wallet encryption password and Ledger PIN. All secrets remain user-managed; use revocable, restricted API keys.
- macOS installer signing/notarization is not guaranteed. Do not treat automated packaging as physical-device certification. Touchscreen Ledger signers outside the currently supported Nano range are not claimed.

## Release integrity and manual Apache PWA deployment

At the immutable `v1.19.0` tag, `package.json.version`, `package-lock.json.version` and the root lockfile package version must equal `1.19.0`. The tag-triggered Electron App Release workflow verifies versions, builds macOS Intel/ARM64, Windows and Linux artifacts, tests Linux package install/remove and checks SHA-256 before automatically publishing a GitHub release.

Desktop packaging and GitHub publication **do not deploy** the Apache-hosted PWA. After release verification and approval, deploy the same tag on the operator's server with:

```bash
~/bin/deploy-nault-master.sh --tag v1.19.0
```

Verify that the PWA and desktop About screen both show **Version 1.19.0** and the tag's Git commit, and retain the prior build for rollback.
