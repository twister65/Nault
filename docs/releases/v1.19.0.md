# Nault 1.19.0 — twister65 fork

This is an independently maintained release of **[twister65/Nault](https://github.com/twister65/Nault)**, **not** an official release of [Nault/Nault](https://github.com/Nault/Nault).

## Highlights since 1.18.8

- **Independent RPC and proof-of-work selection:** choose the wallet RPC node separately from the PoW source, including an explicit Nano.to option and **Best available PoW** as the default on fresh installations. An unlocked, active Nano.to API key is eligible for Best mode regardless of the selected wallet RPC; the public fallback uses Twister32 /pow, then WebGL where supported. Do not submit anonymous paid work requests when credentials are locked or missing. [#86](https://github.com/twister65/Nault/pull/86)
- **Secure optional Nano.to key vault:** locally encrypted AES-256-GCM credentials protected using WebCrypto/PBKDF2; multiple labeled keys, explicit per-session unlock, active-key selection and selective deletion. The vault remains accessible independent of the selected RPC and PoW source. Only authenticated HTTPS `work_generate` requests to `https://rpc.nano.to/` carry the Bearer token. No keys in ordinary wallet RPC, URLs, logs, wallet backups, signed transactions or Ledger IPC. See the [security design](../security/pow-api-key-vault.md), [privacy policy](https://rpc.nano.to/privacy) and [terms](https://rpc.nano.to/terms). [#86](https://github.com/twister65/Nault/pull/86)
- **RPC and network recovery:** improved public-node ranking, explicit Best RPC selection, controlled automatic failover, WebSocket reconnection, node health indicators and offline/online recovery. Protect the wallet RPC choice from transient failures and keep PoW fallback independent. [#77](https://github.com/twister65/Nault/pull/77), [#82](https://github.com/twister65/Nault/pull/82), [#85](https://github.com/twister65/Nault/pull/85), [#86](https://github.com/twister65/Nault/pull/86)
- **Cleaner first launch:** no misleading fiat-price warnings on an unconfigured wallet; Send and Receive are visible but disabled (including route guards) until a wallet exists. [#78](https://github.com/twister65/Nault/pull/78), [#81](https://github.com/twister65/Nault/pull/81)
- **Internationalization and PWA updates:** German translation support, English fallback for unsupported OS locales, and translated update-ready notifications. [#79](https://github.com/twister65/Nault/pull/79), [#83](https://github.com/twister65/Nault/pull/83)
- **Desktop/PWA parity:** shared update and Ledger USB/Bluetooth flow hardening, including native Ledger transport protections without silently retrying a signature. [#71](https://github.com/twister65/Nault/pull/71)
- **Dependency security:** resolve the relevant `follow-redirects` and `minimatch` dependency alerts with isolated maintenance changes. [#74](https://github.com/twister65/Nault/pull/74), [#75](https://github.com/twister65/Nault/pull/75)
- **Broader Linux packaging:** automatically build and verify AppImage, DEB (Debian/Ubuntu/Mint), RPM (Fedora/openSUSE), and Pacman (Arch/Manjaro) artifacts with application-menu integration, alongside Windows and macOS builds. [#80](https://github.com/twister65/Nault/pull/80)

## Scope and release readiness

- **Version:** `package.json.version`, `package-lock.json.version` and `package-lock.json.packages[""].version` are all `1.19.0`. The immutable **`v1.19.0`** tag must be created on the final reviewed `master` commit, never on this preparation branch.
- **Release candidate:** complete CI (Angular 22, regression tests, CodeQL, dependency audit, lint, RPC/PoW tests, PWA build and Electron packaging) must be green after merging this version-bump PR, plus the requested final functional/hardware validation.
- **Known limitations:** Electron 45 migration [#73](https://github.com/twister65/Nault/pull/73) is *not* included. Ledger Stax, Flex, Nano Gen5 and Atom are not validated signers for this release. Hardware compatibility must not be inferred from package build success.
- **Security:** avoid recording seeds, secrets or API keys in diagnostics. Do not automatically retry declined Ledger signatures or replay signed `process` requests. PoW API credentials remain local and are sent only to the exact Nano.to HTTPS work endpoint.

## Publication — explicit approval required

**Preparation does not trigger release.** After functional acceptance, merge the version-bump PR into `master`, verify the final commit and CI, then push the **`v1.19.0`** tag to that commit. The tag-triggered GitHub Actions workflow builds all desktop targets, runs native Linux install/remove checks, verifies package/update metadata and SHA-256 digests, and creates/publishes the GitHub release only after the required artifacts pass validation. Do **not** create the tag, publish, or deploy on Apache as part of release preparation.

## Apache PWA — separate manual deployment

Once the tag and GitHub release are verified, deploy that exact tag on Ubuntu-Salon:

```bash
~/bin/deploy-nault-master.sh --tag v1.19.0
```

Verify that **About Nault** in the Apache-hosted PWA and Desktop reports **1.19.0** and the **same tagged Git commit**; confirm service-worker update, Android navigation/network recovery, Ledger reconnect and PoW selection. Retain the previous Apache release for rollback. No Apache configuration, reverse-proxy, TLS or ModSecurity changes are required.
