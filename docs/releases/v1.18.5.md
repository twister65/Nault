# Nault 1.18.5 — twister65 fork

This is an independently maintained release of **[twister65/Nault](https://github.com/twister65/Nault)**, not an official release from [Nault/Nault](https://github.com/Nault/Nault).

## Changes since 1.18.4

- **Berry Pay RPC compatibility:** avoid empty-wallet balance/frontier requests and unsupported `representatives_online` calls on Berry Pay. Keep the wallet connected when optional representative metadata is not available ([#47](https://github.com/twister65/Nault/pull/47)).
- **Public server maintenance:** remove retired SomeNano and SpyNano choices and safely fall back from previously saved selections ([#46](https://github.com/twister65/Nault/pull/46)).
- **Mobile:** close the navigation drawer with a left swipe ([#44](https://github.com/twister65/Nault/pull/44)); initialize accounts immediately after importing a wallet from QR ([#43](https://github.com/twister65/Nault/pull/43)).
- **Defaults and installation:** select Twister32 RsNano and its dedicated PoW proxy by default ([#42](https://github.com/twister65/Nault/pull/42)); clarify Chrome PWA installation on Android and iOS ([#45](https://github.com/twister65/Nault/pull/45)).
- **Desktop localization:** translate native Electron menus and update dialogs according to the operating-system locale (French, Spanish and English fallback). The native-menu locale can differ from Nault's in-app language.
- **Updater verification:** explicitly pin the Electron Builder GitHub release feed to this fork (`twister65/Nault`). `Check for Updates` now gives an informational response when no new version exists, while update availability prompts for user confirmation before downloading.
- **Release integrity:** synchronize the `1.18.5` version in `package.json` and `package-lock.json`, with CI tests for the localized native labels and pinned update feed.

## Desktop update test

After this release is **published** (not merely drafted), start the installed **1.18.4** desktop AppImage and select **Help → Check for Updates**. A detected 1.18.5 release should offer the new version; choose **Ask Later** first to verify the prompt without replacing the test copy. The check is also attempted at startup. The actual feed inside an already installed 1.18.4 binary is immutable: whether it points to this fork must be confirmed by this test or by inspecting its packaged `resources/app-update.yml`.

- **Linux AppImage:** auto-update is supported when the app is run as a real AppImage (`APPIMAGE` environment variable present); make a backup of the existing AppImage before accepting the update.
- **Windows:** NSIS updater is supported, but these installers are unsigned. Verify on a test machine and expect operating-system trust warnings; never bypass signature validation in production.
- **macOS:** the DMG is unsigned and not notarized. Automatic updates require application signing; install manually.
- **Source/development Electron runs:** no update request is made (`app.isPackaged` guard).

## Verification and security

- The user tested Berry Pay / Ledger Nano X including successful 1 XNO network confirmation (active quorum), PoW and WebSocket subscriptions, without an HTTP 400 in the final console log.
- Require a green Merge Gate, Angular 22 validation, CodeQL checks, and Linux/Windows/macOS packaging before publication.
- Do not treat the green CI as a replacement for the installed 1.18.4 → 1.18.5 updater test.
- Ledger recovery seeds, secrets and APDUs must never be included in diagnostic logs or release notes.

## Downloads

After the tag-triggered workflow publishes the release, retrieve **Nault AppImage (Linux)**, **NSIS installer (Windows)** or **Intel DMG (macOS)** from the assets, together with `SHA256SUMS`. These binaries are unsigned; check the hashes before installation.
