# Nault 1.19.1 — twister65 fork

This independently maintained release of [twister65/Nault](https://github.com/twister65/Nault) is not an official release of the upstream Nault/Nault project.

## Highlights since v1.19.0

- **Twister32 default for new accounts ([#90](https://github.com/twister65/Nault/pull/90)).** New accounts start with `nano_3hn3r6bnnmcy39gu6fgtisgnqh384gmt5mnh71a5xo4cb1d38ps16p8sg5c3` as the representative when their first Nano block is published. Twister32 is prepopulated in the local address book as **Trusted**. Existing opened accounts keep their existing representative until explicitly changed.
- **Representative discovery and monitoring ([#90](https://github.com/twister65/Nault/pull/90)).** Integrates the public [NanoNode.de](https://nanonode.de/representatives) representative list (cached, no wallet account addresses in requests), observed voting activity, voting-weight shares, available node telemetry, and direct read-only links to [NanoTicker](https://www.nanoticker.org/representatives). An improved inline picker supports alias/address search, activity filters, incremental results, and indicative **Good (NanoNode.de)** ratings where sufficient evidence exists.
- **Clear health and trust information.** Network observations from the selected Nano RPC and NanoNode.de are shown separately. Recent votes, voting weight, synchronisation reports and local **Trusted/Avoid** preferences are distinct concepts; missing or potentially forged telemetry is not treated as proof of health. Low voting-weight percentages retain precision. The archived MyNanoNinja dependency is removed.
- **Ledger representative-change feedback.** Only accepted RPC `process` results can produce a success message. Ledger signing errors, rejected signatures, failed changes and partial multi-account outcomes no longer result in false total-success notifications. Representative details remain visible after navigating from a change-required warning and refresh after a successful update.
- **Optional WebAuthn PRF device unlock ([#89](https://github.com/twister65/Nault/pull/89)).** On supported PWA devices, user-enabled device authentication can unlock the Nano.to PoW key vault and supported hot wallets. This does **not** add biometric unlocking to Electron Desktop.
- **Balance and representative refresh ([#91](https://github.com/twister65/Nault/pull/91)).** Adds manual refresh controls in the side-menu balance card and Accounts page, with supported mobile PWA pull-to-refresh gestures.
- **Improved Nano.to key management ([#93](https://github.com/twister65/Nault/pull/93)).** Displays the API-key vault when Nano.to is chosen explicitly or automatically through Best available, with clearer key-entry UI.

## Compatibility, validation and caveats

- Continues Angular 22 and **Electron 44.10.1** from `master` at release preparation. Electron 45 migration is not included.
- PR #90 passed Angular 22 validation, regression tests, desktop build, dependency audit, lint, and CodeQL; Linux Electron behavior was then accepted by the maintainer. PRs #89, #91 and #93 were separately merged. Other platforms should be smoke-tested after packaging.
- NanoNode.de is a third-party observer, not an authority for representative health. The snapshot is time-limited; an unavailable or stale monitoring API does not change wallets, delegation, local trust or consensus state. NanoTicker is a link for users to inspect extra health information, not a hidden automatic scoring service.
- Keep supported Ledger Nano S Plus USB and Nano X USB/BLE flows independent of representative discovery. Windows/macOS hardware tests and signing/notarization are not implied by successful CI.

## Release procedure and Apache PWA deployment

**Preparation is not publication.** The `v1.19.1` tag must not be created until the version-bump changes have been merged, the CI/release gate has passed, and GitHub publication is authorized.

At the exact tagged commit, the versions in `package.json`, `package-lock.json`, and `package-lock.json.packages[""].version` must all equal **1.19.1**.

Pushing `v1.19.1` triggers the Electron App Release workflow. It packages Windows installer, macOS Intel/Apple Silicon DMG and ZIP, and Linux x64 AppImage/DEB/RPM/Pacman. It checks native Linux installation/removal, updater metadata, OS-grouped release assets and SHA256SUMS. **The workflow automatically publishes the release** only after the platform builds and validations succeed.

Desktop publication does not deploy the Apache-hosted PWA. After publication and integrity review, deploy the exact tag manually:

```bash
~/bin/deploy-nault-master.sh --tag v1.19.1
```

Verify both Desktop and PWA About panels show **1.19.1** and the expected tagged commit. Confirm balances, representatives and supported Ledger connections, and retain the prior Apache release for rollback.
