# Nault 1.19.6 — twister65 fork

This is a release of the independently maintained [twister65/Nault](https://github.com/twister65/Nault) fork, **not** an official upstream Nault/Nault release.

## Highlights since v1.19.5

- **Nine new UI languages ([#119](https://github.com/twister65/Nault/pull/119)).** Adds Norwegian Bokmål (`nb`), Danish (`da`), Dutch (`nl`), Finnish (`fi`), Brazilian Portuguese (`pt-BR`), Italian (`it`), Japanese (`ja`), Korean (`ko`) and Simplified Chinese (`zh-CN`). Each dictionary contains 897 keys matching the English source. The existing English, French, Spanish, German and Traditional Chinese (Hong Kong) dictionaries remain available (14 interface languages in total). Transloco lazy-loads the dictionaries and recognizes selected regional OS/browser locale variants; Simplified Chinese and Traditional Chinese are kept distinct.
- **Language-specific Nano merchant badges ([#119](https://github.com/twister65/Nault/pull/119)).** Merchant Mode selects the corresponding official Nano “Accepted here” SVG, with an explicit mapping where Nano asset codes differ from application locale IDs (for example, Korean `ko` → `kr`). If a candidate asset cannot be loaded, Nault tries an alternative official filename before displaying its local Nano badge plus the translated message. **Some candidate filenames have not been verified against the live assets server**; confirm all languages in a browser before final publication.
- **Nano symbol and fiat balance labels ([#117](https://github.com/twister65/Nault/pull/117)).** Preserves the selected fiat currency code next to converted balances and consistently renders the Nano text symbol `Ӿ` (U+04FE) in place of the legacy `XNO` ticker where applicable. The official graphic asset is used for the double-stroke Nano symbol. This does not alter amounts, conversion calculations or signed transactions.
- **Electron native menu and dialog language synchronization ([#118](https://github.com/twister65/Nault/pull/118)).** The native menu follows the selected Nault language, including after startup with a saved preference, and supported updater and Ledger Bluetooth dialogs follow it too. The native Electron dictionary currently supports **English, French, Spanish, German and Traditional Chinese (Hong Kong)**. When the user selects one of the nine newly added Angular languages, the native menu/dialog text falls back to English; those nine **native** dictionaries are not part of this release.

## Compatibility and downloads (only after release publication)

- **Windows x64:** NSIS EXE installer.
- **macOS Intel x64:** DMG and updater ZIP.
- **macOS Apple Silicon arm64:** DMG and updater ZIP. Both macOS architectures are required; do not silently skip Apple Silicon if a runner is busy.
- **Linux x64:** portable AppImage, DEB (Debian/Ubuntu/Mint), RPM (Fedora/openSUSE) and Pacman (Arch/Manjaro).
- The tag-triggered workflow generates and verifies update metadata, SHA-256 checksums, Linux install/remove smoke tests and native artifact provenance attestations before automatically publishing the GitHub release.

The release retains the existing Electron 45.4.1 and Angular 22.3.0 dependency baseline. No RPC, PoW, Nano signing or Ledger transport protocol changes are intentionally introduced by these localization PRs.

## Validation and known limitations

### Automated checks
- [ ] On the final release preparation PR: Angular 22 validation; full Angular tests; `npm run test:i18n` (all 14 dictionaries, keys/interpolations, Nano sign); Electron native locale regression; lint; dependency audit; CodeQL; Merge gate.
- [ ] Confirm packaging previews and install/remove smoke tests for Windows, Linux, macOS Intel and Apple Silicon; review any failed job before proceeding.
- [ ] Verify `package.json.version`, `package-lock.json.version` and `package-lock.json.packages[""].version` all equal **1.19.6**.

### Functional release-candidate checks (not claimed as completed)
- [ ] Switch among **all 14 languages**, including locale persistence after restart, long labels, bidirectional font fallback issues and mobile layout; verify Chinese `zh-CN` versus `zh-HK`.
- [ ] Run merchant QR checkout in representative languages (particularly Italian, Japanese, Korean and both Chinese variants). Verify the **actual loaded localized badge** rather than only the alt text, including offline fallback and correct sign `Ӿ`.
- [ ] Review security- and finance-sensitive machine-assisted translations with native speakers: send/receive, wallet unlock, backup, seed import, destructive actions and PoW key vault messages.
- [ ] For Electron, verify native menu updates on language change, saved language on restart, updater dialogs and Ledger Bluetooth connection dialogs. Confirm English native fallback for newly added UI locales.
- [ ] On the exact release candidate, test normal send/receive and pending receive after unlocking, representatives/balance refresh, PWA Service Worker upgrade/offline-online recovery, RPC/WebSocket and PoW failover, and physical Ledger signing/rejection and reconnect (Nano S USB, Nano X USB/BLE where available). CI packaging alone does not establish physical-device or fresh-install compatibility.

**Existing limitation:** Windows browser/PWA WebAuthn PRF device unlock remains disabled pending an independently verified Windows fix; the password fallback remains available. No successful macOS code signing/notarization is implied by packaging CI.

## Release and deployment procedure

Preparing this branch and these release notes **does not** create a tag, publish GitHub assets or deploy the Apache-hosted PWA.

1. Merge the release preparation PR into `master` **after** the CI, localization and functional review gates have been satisfied.
2. Confirm the exact `master` commit and three matching `1.19.6` version values. After explicit release approval, create and push the **annotated `v1.19.6` tag** at that commit. **Pushing this tag triggers the Electron App Release workflow, which automatically publishes GitHub release assets after its gates pass**; it is not a harmless staging step.
3. Verify the published release includes Windows EXE, both macOS DMGs and ZIPs, Linux AppImage/DEB/RPM/Pacman, updater metadata, checksums and attestations. Validate the version and Git SHA shown in **About Nault**.
4. Treat the **production PWA deployment as a separate approval** after desktop release verification. Use the production host's release-aware script with `--tag v1.19.6`; check the Service Worker, About Nault version/commit, TLS, wallet functions and existing Nano/Banano proxies before removing the old deployment. Retain v1.19.5 for rollback.
